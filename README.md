# 真种草 · 新品牌买点验证工作台

> 先验证为什么值得买，再决定下一笔预算投在哪里。

面向新品牌的产品决策 Demo：整理卖点证据、提出待验证买点、生成小规模体验计划，并根据反馈更新下一轮行动。

这是个人作品集项目，使用 AI 辅助设计和实现。当前为可配置模型接口的全栈版；此前纯前端规则版用于受限环境演示。这里不声称已经取得真实商业效果。

## 能做什么

- 根据产品宣称与材料，拆分证据条目，展示支持范围、缺口和引用编号。
- 生成待验证买点与体验采集计划。
- 将体验反馈与初次分析对照，更新建议并生成可复制的 brief。
- 输入或反馈改变后使旧结果失效，避免串用分析。
- 内置滤杯与 A/B 反馈作为模拟材料，可输入自定义产品。

模型辅助分析不等于独立核验：用户需确认产品事实、材料真实性与最终商业决定。

## 技术与模型要求

React + Vite 前端、Express 后端、Node.js 22 或更高，以及 pnpm 11。

后端通过可配置的 `POST /chat/completions` 服务调用模型。服务须接受 `model`、`messages`、`max_tokens`、`stream:false`，并返回 `choices[0].message.content` 字符串。支持该格式的服务可尝试接入，但未逐一测试所有供应商。密钥仅保存在后端环境变量。

## 本地启动

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
# 在 .env 中填写模型地址、密钥和模型名
pnpm test
pnpm build
pnpm start
```

访问 http://localhost:3000 。更改配置后需重启服务。

| 环境变量 | 含义 |
| --- | --- |
| MODEL_BASE_URL | API 基础地址，通常包含 /v1，不包含 /chat/completions |
| MODEL_API_KEY | 你自己的服务密钥，不要提交到 GitHub |
| MODEL_NAME | 服务实际支持的模型名称 |
| PORT | 服务端口，默认 3000 |

未配置模型时页面可以打开，但分析会提示需要配置；不会伪装成实时分析。

## 演示路径

载入示例 → 初次分析 → 载入模拟反馈 A 或 B → 更新决策 → 查看引用与下一步 → 复制 brief。

案例：釉色差异可能吸引用户，也可能造成预期落差；新反馈应影响验证方向，而不能证明“可机洗”或“风味提升”等效果成立。

## 部署

这是包含后端的项目，GitHub 仅托管源码，GitHub Pages 不能运行 Express。

在支持 Node.js 的托管环境中安装依赖、执行 `pnpm build`，并运行 `pnpm start`。在托管平台设置上述模型环境变量。暂未提供在线全栈演示链接。

当前是作品集 Demo，没有用户登录、配额和访问控制。公开部署调用真实付费模型前，应设置访问限制与额度控制，避免访客任意消耗你的模型额度。

## 验证范围与边界

- 模型适配器测试覆盖请求构造、配置缺失、鉴权失败、空响应与超时。
- 自动测试使用模拟服务，不消耗真实模型额度；真实模型效果取决于你配置的服务。
- 模拟数据不代表真实调研。小样本反馈不代表统计显著性或市场结论。
- 不生成可直接发布的种草正文，不预测销量、收益或 ROI。
